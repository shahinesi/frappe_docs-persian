# واژه‌نامهٔ پایه

| English | فارسی پیشنهادی | یادداشت |
|---|---|---|
| DocType | DocType (نوع سند) | نام فنی حفظ شود؛ در توضیح عمومی «نوع سند» به‌کار رود. |
| Docstatus | وضعیت سند (`docstatus`) | یکی از Draft، Submitted یا Cancelled است؛ مقدار فنی در کد دست‌نخورده بماند. |
| Document | سند | رکوردی از یک DocType. |
| Workspace | فضای کاری | نام فنی Workspace در متن API حفظ شود. |
| Web Form | Web Form (فرم وب) | نام DocType و برچسب فنی حفظ شود؛ در توضیح عمومی «فرم وب» به‌کار رود. |
| Web Form Request | درخواست Web Form | سندی برای تولید پیوند خصوصی با کلید دسترسی به فرم. |
| Workspace Manager | مدیر فضای کاری (Workspace Manager) | نام نقش دسترسی حفظ شود؛ System Manager به‌تنهایی این نقش را ندارد. |
| Sidebar | نوار کناری | در UI برای نوار پیمایش کنار میزکار. |
| Workspace Sidebar | نوار کناری فضای کاری (Workspace Sidebar) | نام رکورد فنی حفظ شود. |
| Desk | میزکار | رابط اصلی کاربری Frappe. |
| Workflow | گردش‌کار | مراحل و قواعد گذار وضعیت. |
| Role | نقش | مجوزها به نقش وابسته‌اند. |
| User ID | شناسهٔ کاربر (User ID) | نام فنی شناسه حفظ شود؛ معمولاً بر اساس ایمیل ساخته می‌شود. |
| Rename | تغییر نام (Rename) | نام کنش UI حفظ شود؛ برای تغییر شناسهٔ یکتای سند. |
| Permission | مجوز | برای سطح دسترسی؛ با «دسترسی» یکدست شود. |
| Export | خروجی‌گرفتن (Export) | در عنوان دکمه و مجوز UI، برچسب انگلیسی هم حفظ شود. |
| Permission Type | نوع مجوز | نوع‌های مجوز سفارشی به کنش‌های خاص مانند تأیید سند اختصاص می‌یابند. |
| Resource Server | سرور منبع (Resource Server) | سرویس‌دهندهٔ منابع محافظت‌شده در OAuth2. |
| Authorization Server | سرور مجوزدهی (Authorization Server) | سروری که توکن دسترسی صادر می‌کند. |
| Client | کلاینت (Client) | برنامه‌ای که برای دسترسی به منبع، توکن می‌گیرد. |
| OAuth2 | OAuth2 | چارچوب مجوزدهی؛ نام استاندارد حفظ شود. |
| Field | فیلد | نام کلید فنی ترجمه نشود. |
| Fetch From | Fetch From (دریافت از فیلد پیوندشده) | نام ویژگی UI حفظ شود؛ مقدار پیکربندی با نام فنی فیلدها نوشته می‌شود. |
| Data Masking | پوشاندن داده | ویژگی پوشاندن مقدار فیلدهای حساس بر اساس مجوز. |
| Mask | Mask (مجوز پوشاندن) | برچسب و مقدار فنی مجوز حفظ شود. |
| Report | گزارش | نام نوع گزارش طبق رابط محصول. |
| Dashboard | داشبورد | در UI فارسی محصول با همین معادل هماهنگ شود. |
| Customer | مشتری | نام DocType فنی `Customer` تغییر نکند. |
| Company | شرکت | شخصیت حقوقی ERPNext؛ نام DocType فنی حفظ شود. |
| Chart of Accounts | Chart of Accounts (درخت حساب‌ها) | ساختار حساب‌های گروهی و دفترکل شرکت. |
| General Ledger | دفترکل کل | گزارش ثبت‌های بدهکار و بستانکار حساب‌ها. |
| Accounts Receivable | حساب‌های دریافتنی | مطالبات مشتریان؛ نام گزارش رابط حفظ شود. |
| Accounts Payable | حساب‌های پرداختنی | بدهی به تأمین‌کنندگان؛ نام گزارش رابط حفظ شود. |
| Cost of Goods Sold | بهای تمام‌شدهٔ کالای فروش‌رفته | هزینهٔ مستقیم کالای فروخته‌شده؛ Account Type فنی حفظ شود. |
| Parent Company | شرکت والد | شرکت بالادستی در ساختار شرکت‌های والد و فرزند. |
| Reporting Currency | ارز گزارش‌گیری | ارز افزوده برای گزارش‌ها در کنار ارز پایهٔ شرکت. |
| Supplier | تأمین‌کننده | نگارش ثابت در همهٔ محصولات. |
| Item | کالا | در ERPNext؛ شناسهٔ `Item` حفظ شود. |
| Sales Order | سفارش فروش | نام سند ERPNext. |
| Purchase Order | سفارش خرید | نام سند ERPNext. |
| Lead | سرنخ | با فرصت فروش اشتباه نشود. |
| Deal | معامله | رکورد فروش واجد شرایط در Frappe CRM؛ با Lead یکی نیست. |
| Opportunity | فرصت فروش | مرحلهٔ پس از سرنخ در فرایند فروش. |
| Accounting Dimension | بُعد حسابداری | بخش‌بندی مدیریتی ثبت‌ها بدون تکثیر حساب‌های دفترکل. |
| Reference Document Type | نوع سند مرجع | DocTypeای که مقادیر قابل‌انتخاب یک بُعد از رکوردهایش می‌آیند. |
| Dimension Defaults | پیش‌فرض‌های بُعد | جدول مقدارهای پیش‌فرض و قواعد هر شرکت در ERPNext. |
| Ticket | تیکت | در Helpdesk؛ عنوان رابط موجود بررسی شود. |
| Employee | کارمند | در ماژول‌های منابع انسانی Frappe. |
| Branch | شعبه | شعبهٔ سازمانی؛ نام فنی DocType در مسیرها و کد حفظ شود. |
| Designation | عنوان شغلی | عنوان رسمی شغل کارمند؛ نام فنی DocType حفظ شود. |
| Employment Type | نوع استخدام | دسته‌بندی شرایط استخدام، دستمزد و استحقاق مرخصی. |
| Employee Group | گروه کارکنان | گروه‌بندی کارکنان؛ نام فنی DocType در API حفظ شود. |
| Leave | مرخصی | در بافت HR؛ نوع و سیاست مرخصی را ترجمه نکنید. |
| Attendance | حضور و غیاب | سابقهٔ حضور کارکنان. |
| Expense Claim | درخواست هزینه | سند بازپرداخت هزینهٔ کارکنان. |
| Appraisal | ارزیابی عملکرد | چرخه و سند بررسی عملکرد کارکنان. |
| Appraisal Cycle | چرخهٔ ارزیابی عملکرد | بازه و فرایند برنامه‌ریزی ارزیابی کارکنان. |
| Feedback | بازخورد | نظر ثبت‌شده دربارهٔ عملکرد یا مصاحبه؛ نام فنی سند حفظ شود. |
| KRA | شاخص کلیدی نتیجه (KRA) | شاخص ارزیابی نتیجهٔ مورد انتظار؛ سرواژه حفظ شود. |
| Vehicle Log | گزارش کارکرد خودرو | ثبت داده‌ها و هزینه‌های مرتبط با استفاده از خودرو. |
| Interview Round | مرحلهٔ مصاحبه | یکی از مراحل فرایند مصاحبهٔ استخدامی. |
| Assignment Rule | قاعدهٔ تخصیص | قاعدهٔ خودکار واگذاری تیکت به کارشناسان در Helpdesk. |
| Issue | درخواست پشتیبانی | در بافت Helpdesk؛ با Issue فنی اشتباه نشود. |
| Dataset | مجموعه‌داده | در Insights. |
| Chart | نمودار | نام فنی تنظیمات و API حفظ شود. |
| Query | پرس‌وجو | SQL Query در متن فنی حفظ می‌شود. |
| Full-text search | جست‌وجوی تمام‌متن | نام کلاس/API `FullTextSearch` بدون تغییر بماند. |
| Search index | نمایهٔ جست‌وجو | برای دادهٔ ساختاریافتهٔ قابل جست‌وجو. |
| Sync | همگام‌سازی | یکدست در تمام محصولات. |
| Site | سایت | در معنای Frappe site؛ نه وب‌سایت مگر بافت عمومی. |
| Bench | Bench | ابزار خط فرمان Frappe؛ نام محصول ترجمه نشود. |
| Allow on Submit | Allow on Submit (ویرایش پس از ثبت) | نام ویژگی فنی و برچسب UI حفظ شود؛ توضیح فارسی در متن بیاید. |
| Accounting Period | دورهٔ حسابداری | نام DocType فنی `Accounting Period` حفظ شود. |
| Closed Documents | اسناد بسته‌شده | عنوان جدول تنظیمات ERPNext؛ نام فیلد فنی در صورت نیاز حفظ شود. |
| Agent | کارشناس پشتیبانی | در Frappe Helpdesk برای نقش agent؛ از «عامل» استفاده نشود. |
| Ticket | تیکت | در Helpdesk؛ با سندهای مالی ERPNext اشتباه نشود. |
| Workbook | کارپوشه | در Insights برای فضای کاری تحلیل؛ نام فنی `Workbook` حفظ شود. |
| Chart | نمودار | نوع نمایش داده در Insights؛ API و نام DocType دست‌نخورده بماند. |
