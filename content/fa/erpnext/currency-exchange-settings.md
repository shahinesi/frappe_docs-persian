تراکنش‌های بین‌المللی Nova Industries گاهی به نرخ بازار نیاز دارند؛ زمانی که تیم مالی نرخی را دستی ذخیره نکرده باشد.

کاربر فروش Nova یک صورتحساب EUR می‌سازد، اما تیم مالی برای آن تاریخ نرخ دستی وارد نکرده است. ERPNext می‌تواند کاربر را متوقف کند یا برای دریافت نرخ از یک سرویس آنلاین نرخ ارز کمک بگیرد. تنظیمات تبدیل ارز این روش جایگزین را از طریق ارائه‌دهنده، نقطهٔ پایانی، پارامترهای درخواست، اعتبارنامه و نگاشت نتیجه کنترل می‌کند.

این تنظیم سراسری است؛ بنابراین یک پیکربندی نادرست می‌تواند بر تراکنش‌ها و ارزش‌گذاری مجدد پایان دوره در چند شرکت اثر بگذارد. اگر نرخ بازار پذیرفتنی است از آن استفاده کنید؛ اگر تیم مالی فقط رکوردهای تأییدشدهٔ [نرخ تبدیل ارز (تبدیل ارز)](currency-exchange.md) را مجاز می‌داند، ارائه‌دهنده را غیرفعال کنید. این صفحه کمک می‌کند پیش از وابسته‌شدن کاربران، ارائه‌دهنده را پیکربندی و آزمایش کنید.

## پیش از شروع

جفت‌ارزهای لازم، تاریخ‌های تراکنش و نوع نرخ‌ها را فهرست کنید. تأیید کنید ارائه‌دهنده علاوه بر نرخ‌های جاری، تاریخ‌های گذشته را نیز پوشش می‌دهد یا خیر. مسئول نگهداری اعتبارنامهٔ ارائه‌دهنده، تأیید منبع نرخ، رسیدگی به قطعی و روش جایگزین دستی را تعیین کنید.

رکوردهای [ارز (واحد پول)](currency.md) موردنیاز را فعال کنید. کنترل‌های نرخ قدیمی در [تنظیمات حساب‌ها](accounts-settings.md) را بررسی کنید؛ زیرا پیش از فراخوانی ارائه‌دهنده، رکورد دستی معتبر در اولویت است. اگر **نرخ های مبادله قدیمی را مجاز کنید** فعال باشد، ممکن است نرخ دستی قدیمی تا مدت نامحدود در اولویت بماند.

## بررسی ارائه‌دهندهٔ پیکربندی‌شده

1. تنظیمات تبدیل ارز را باز کنید.
2. اگر به روش جایگزین ارائه‌دهنده نیاز دارید، مطمئن شوید **غیرفعال** انتخاب نشده باشد.
3. ارائه‌دهندهٔ خدمات را انتخاب کنید.
4. نقطه پایانی API و پروتکل را بررسی کنید.
5. فقط برای ارائه‌دهنده‌ای که کلید دسترسی لازم دارد، کلید دسترسی را وارد کنید.
6. Parameters درخواست و نگاشت‌های کلید نتیجه را بررسی کنید.
7. ذخیره کنید و سپس تنظیم را از یک تراکنش ارزیِ پیش‌نویس بیازمایید.

گزینه‌های نسخهٔ فعلی develop شامل `frankfurter.dev`، `frankfurter.dev - v2`، `exchangerate.host` و `Custom` هستند. Frankfurter v2 از ارزهای بیشتری نسبت به پیکربندی قدیمی v1 پشتیبانی می‌کند. Exchangerate.host به کلید دسترسی نیاز دارد. پوشش ارائه‌دهنده و شرایط تجاری ممکن است تغییر کند؛ پیش از انتشار، آن‌ها را مستقیماً نزد ارائه‌دهنده اعتبارسنجی کنید.

## فیلدهای مهم و مفهوم آن‌ها

| فیلد | مفهوم |
| --- | --- |
| غیرفعال | درخواست به ارائه‌دهنده را متوقف می‌کند. ERPNext همچنان می‌تواند از رکوردهای ذخیره‌شدهٔ واجد شرایط تبدیل ارز استفاده کند. |
| ارائه‌دهندهٔ خدمات | نگاشت ازپیش‌تعریف‌شدهٔ ارائه‌دهنده را بارگذاری می‌کند یا اجازهٔ پیکربندی سفارشی می‌دهد. |
| نقطه پایانی API | الگوی نشانی‌ای که ERPNext فراخوانی می‌کند. می‌تواند جای‌نگهدارهایی مانند `{transaction_date}`، `{from_currency}` و `{to_currency}` داشته باشد. |
| استفاده از پروتکل HTTP | به‌جای HTTPS از HTTP استفاده می‌کند. این گزینه را خالی بگذارید، مگر آنکه یک سرویس داخلی مورداعتماد مشخصاً به HTTP نیاز داشته باشد. |
| کلید دسترسی | اعتبارنامه‌ای که بعضی ارائه‌دهندگان لازم دارند. مانند هر راز API بیرونی از آن محافظت کنید. |
| مولفه های | جفت‌های کلید و مقداری که همراه درخواست فرستاده می‌شوند. مقدارها می‌توانند جای‌نگهدارهای پشتیبانی‌شده داشته باشند. |
| کلید نتیجه | مسیری برای استخراج نرخ عددی از پاسخ ارائه‌دهنده. |
| URL مثال | پیش‌نمایشی برای اعتبارسنجی قالب درخواست نهایی. |

رازها را در مستندات، تصویر صفحه، پیام پشتیبانی یا اسکریپت‌های سمت کاربر قرار ندهید. مجوز نوشتن در این تنظیم را محدود کنید.

برای محدودکردن افرادی که می‌توانند ارائه‌دهنده یا اعتبارنامه‌هایش را تغییر دهند، از [مجوزهای مبتنی بر نقش](https://docs.frappe.io/erpnext/role-based-permissions) استفاده کنید. منبع نرخ یک کنترل حسابداری است، نه صرفاً ترجیحی فنی. مسئول، تاریخ تمدید، ارائه‌دهندگان تأییدشده، جفت‌ارزهای پشتیبانی‌شده و روش جایگزین دستی را در رویهٔ عملیاتی مالی ثبت کنید.

## انتخاب ارائه‌دهنده

### Frankfurter v2

اگر ارزهای پشتیبانی‌شده و پوشش تاریخی آن با نیازتان سازگار است، برای نرخ بدون کلید با منبع متمرکز از پیکربندی ازپیش‌تعریف‌شدهٔ v2 استفاده کنید. نقطهٔ پایانی پیکربندی‌شده در سایت نمایشی، نرخ ارز مبدأ، ارز مقصد و تاریخ تراکنش را درخواست می‌کند.

### Frankfurter v1

نقطهٔ پایانی قدیمی‌تر ارزهای کمتری را پوشش می‌دهد. فقط زمانی آن را نگه دارید که یکپارچه‌سازی موجود با فهرست پشتیبانی‌شدهٔ آن آزمایش شده باشد. برای راه‌اندازی‌های تازه ابتدا v2 را ارزیابی کنید.

### Exchangerate.host

این ارائه‌دهنده سرویس تجاری گسترده‌تری دارد، اما پیکربندی ازپیش‌تعریف‌شدهٔ فعلی به کلید دسترسی نیاز دارد. پیش از استفاده، طرح رایگان یا پولی، محدودیت نرخ درخواست، پوشش تاریخی، مجوز و زمان دسترس‌پذیری آن را بررسی کنید.

### سفارشی

برای سرویس خزانه‌داری تأییدشده یا نقطهٔ پایانی داخلی نرخ از گزینهٔ **سفارشی** استفاده کنید. نشانی، پارامترها و مسیر نتیجه را با دقت پیکربندی کنید. پاسخ باید نرخ عددی را در جهتی ارائه کند که ERPNext درخواست کرده است.

## آشنایی با اولویت جست‌وجوی نرخ

وقتی ERPNext برای جهتی مشخص، تاریخی مشخص و زمینهٔ خرید یا فروش نرخ می‌خواهد، ابتدا رکوردهای ذخیره‌شدهٔ تبدیل ارز را جست‌وجو می‌کند. اگر هیچ‌کدام واجد شرایط نباشند، ارائه‌دهنده فراخوانی می‌شود. اگر ارائه‌دهنده شکست بخورد یا مقدار قابل‌استفاده‌ای برنگرداند، ERPNext از کاربر می‌خواهد رکورد دستی بسازد.

این اولویت زمانی مهم است که کاربران می‌گویند سامانه از نرخ بازار استفاده نمی‌کند. علت ممکن است وجود رکورد ذخیره‌شدهٔ واجد شرایط باشد، نه ارائه‌دهنده. پیش از تغییر پیکربندی API، [چرا فیلد نرخ ارز غیرفعال است؟](exchange-rate-field-frozen.md) و تنظیمات نرخ قدیمی را بررسی کنید.

## آزمایش پیکربندی

یک [فاکتور فروش](https://docs.frappe.io/erpnext/sales-invoice) یا [فاکتور خرید](https://docs.frappe.io/erpnext/purchase-invoice) پیش‌نویس با تاریخ یک روز کاری شناخته‌شده بسازید. ارز خارجی پشتیبانی‌شده‌ای انتخاب کنید و موارد زیر را بررسی کنید:

- نرخ تبدیل مقداردهی شود؛
- جهت نرخ در برچسب فیلد درست باشد؛
- جمع به ارز شرکت با نرخ مطابقت داشته باشد؛
- برای تاریخ گذشته، نرخ تاریخی معقولی برگردد؛
- جفت‌ارز عمداً پشتیبانی‌نشده، فرایند جایگزینی روشنی داشته باشد؛
- کلید API یا جزئیات پاسخ برای کاربران عادی افشا نشود.

[ثبت پرداخت](https://docs.frappe.io/erpnext/payment-entry) را هم آزمایش کنید؛ چون ارزهای حساب مبدأ و مقصد آن ممکن است جهتی متفاوت درخواست کنند. [تجدید ارزیابی نرخ ارز](exchange-rate-revaluation.md) را جداگانه برای تاریخ بستن دوره آزمایش کنید.

پس از ارتقای برنامه یا تغییر پیکربندی ارائه‌دهنده، آزمایش را تکرار کنید. مقدار برگشتی را برای تاریخی شناخته‌شده با مرجعی مستقل و تأییدشده مقایسه کنید و مطمئن شوید درخواست به‌طور غیرمنتظره از رکورد دستی قدیمی‌تری استفاده نمی‌کند.

## غیرفعال‌کردن روش جایگزین ارائه‌دهنده

اگر همهٔ نرخ‌ها باید از اطلاعات پایهٔ دستیِ تأییدشده یا فرایندی کنترل‌شده تأمین شوند، **غیرفعال** را انتخاب کنید. پیش از این کار، رکوردهای تاریخ‌دار و جهت‌دار موردنیاز را بسازید و رفتار سامانه را هنگام نبود نرخ بیازمایید. غیرفعال‌کردن ارائه‌دهنده به‌تنهایی گردش‌کار تأیید مبتنی بر هشدار ایجاد نمی‌کند.

اگر تیم مالی نرخ‌ها را وارد می‌کند، از [واردکردن داده‌ها (درون‌بُرد داده)](data-import.md) همراه با قالب کنترل‌شده و فرایند اعتبارسنجی استفاده کنید. اجازه ندهید رکوردهای تکراری یا دارای جهت اشتباه بدون توجه انباشته شوند.

## عیب‌یابی

### ERPNext برای یک ارز نرخ پیدا نمی‌کند

تأیید کنید ارائه‌دهنده از هر دو ارز و تاریخ تاریخی درخواستی پشتیبانی می‌کند. ممکن است ارائه‌دهنده USD و EUR را پوشش دهد اما از یک ارز منطقه‌ای پشتیبانی نکند. ارائه‌دهندهٔ جایگزینِ تأییدشده را امتحان کنید یا رکورد دستی بسازید.

### ارائه‌دهنده پیکربندی شده اما نرخ دیگری نمایش داده می‌شود

تبدیل ارز را برای یافتن رکورد دستی منطبق جست‌وجو کنید. تاریخ تراکنش، جهت تبدیل، گزینهٔ خرید یا فروش، نرخ های مبادله قدیمی را مجاز کنید و روزهای کهنه را بررسی کنید.

### ارائه‌دهندهٔ سفارشی داده برمی‌گرداند اما ERPNext مقدار صفر می‌خواند

مسیر کلید نتیجه را بازبینی کنید و مطمئن شوید مقدار استخراج‌شده عددی است. نشانی درخواست و ساختار پاسخ را بدون افشای اعتبارنامه‌ها مقایسه کنید.

### نرخ‌های تاریخی ناموفق‌اند اما نرخ‌های جاری کار می‌کنند

ممکن است ارائه‌دهنده یا طرح انتخابی از تاریخ‌های گذشته پشتیبانی نکند. از ارائه‌دهنده‌ای با پوشش مناسب استفاده کنید یا رکوردهای تاریخی تبدیل ارز تأییدشده را وارد کنید.

## پرسش‌های متداول

### آیا ERPNext همیشه ارائه‌دهندهٔ پیکربندی‌شده را فراخوانی می‌کند؟

خیر. رکورد دستیِ واجد شرایط تبدیل ارز در اولویت است.

### کدام ارائه‌دهنده را انتخاب کنم؟

بر اساس پوشش ارزها، پشتیبانی از تاریخ‌های گذشته، سیاست دقت، مجوز، محدودیت درخواست، قابلیت اطمینان و امنیت تصمیم بگیرید. یک ارائه‌دهندهٔ برترِ همگانی وجود ندارد.

### آیا نرخ ارائه‌دهنده خودکار در دفتر کل ثبت می‌شود؟

خیر. نرخ دریافت‌شده در یک سند قرار می‌گیرد. دفتر کل فقط وقتی تغییر می‌کند که تراکنش حسابداریِ قابل ثبت نهایی یا ثبت در دفتر روزنامه حاصل از آن ثبت نهایی شود.

### آیا هر شرکت می‌تواند ارائه‌دهندهٔ جداگانه‌ای داشته باشد؟

تنظیمات تبدیل ارز یک singleton در سطح سایت است. اگر شرکتها به منابع تأییدشدهٔ جدا نیاز دارند، از رکوردهای دستیِ کنترل‌شده یا سفارشی‌سازی استفاده کنید.

### آیا برای ارائه‌دهندهٔ بیرونی HTTP را فعال کنم؟

خیر؛ برای سرویس‌های بیرونی از HTTPS استفاده کنید. HTTP را به معماری داخلی‌ای محدود کنید که عمداً ایمن‌سازی شده باشد.
