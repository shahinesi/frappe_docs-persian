فیلدهای وابسته رابطهٔ والد و فرزند دارند؛ مانند فیلدهای دسته‌بندی و Sub-دسته‌بندی. فقط وقتی دسته‌بندی انتخاب شده باشد، زیر‌دسته‌های مرتبط نمایش داده می‌شوند. به همین ترتیب، می‌توانید فقط پس از انتخاب دستهٔ اصلی مسئله‌های مشخص را نشان دهید یا محصولات را بر اساس نوع دسته‌بندی فهرست کنید.

این نوع وابستگی را می‌توان با قابلیت **فیلد Dependency** ساخت. فقط فیلدهای نوع **انتخاب کردن** و **پیوند** پشتیبانی می‌شوند.

> توجه: این قابلیت فقط هنگام ساخت تیکت کاربرد دارد.

## افزودن فیلد سفارشی

1. با **Customize فرم** یک فیلد تازه بسازید. برای این کار به میزکار بروید، DocType **تیکت** را باز کنید و **Customize فرم** را انتخاب کنید. برای جزئیات بیشتر، [این راهنما](../erpnext/customize-form.md) را ببینید.
2. نام فیلدی را که می‌خواهید کاربر هنگام ساخت تیکت پر کند کپی کنید.
3. در میزکار، DocType **تیکت Template** را باز کنید و سندی با نام **default** را انتخاب کنید. نام فیلد را در جدول بخش **fields** جای‌گذاری کنید. در فیلد **Visible به** می‌توانید **همه افراد** را انتخاب کنید تا همه بتوانند فیلد را پر کنند؛ یا بر اساس نیاز آن را به نقش **کارشناس پشتیبانی** یا **مشتری** محدود کنید.

## پیاده‌سازی فیلد Dependency

پس از افزودن فیلدهای سفارشی لازم به **تیکت Template**، می‌توانید وابستگی فیلدها را به یکی از دو روش زیر پیاده‌سازی کنید:

1. ساخت وابستگی از رابط کاربری پرتال
2. استفاده از **HD فرم Script** در میزکار

### ساخت وابستگی از رابط کاربری پرتال

1. از منوی کاربر **تنظیمات** را باز کنید.
2. زبانهٔ **فیلد Dependencies** را انتخاب و روی **جدید** کلیک کنید.
3. فیلد والد و فیلد فرزند را انتخاب کنید. فیلدهایی که قبلاً از رابط **فیلد Dependency** به کار رفته‌اند، هنگام ساخت وابستگی جدید در فهرست فیلد فرزند در دسترس نیستند.

   > توجه: مطمئن شوید فیلدها به الگوی **تیکت** (الگوی پیش‌فرض) اضافه شده‌اند.

4. برای هر مقدار فیلد والد، مقدارهای متناظر فیلد فرزند را انتخاب کنید که باید هنگام انتخاب آن مقدار والد در دسترس باشند. اگر برای مقدار والد هیچ مقدار فرزندی انتخاب نشود، فیلد فرزند قابل‌ویرایش نخواهد بود.

#### کنترل نمایش فیلد فرزند

شرط نمایش یا پنهان‌بودن فیلد فرزند را بر اساس مقدار فیلد والد تعیین کنید. اگر این شرط غیرفعال باشد، فیلد فرزند همیشه نمایش داده می‌شود.

اگر شرط را فعال کنید، می‌توانید تعیین کنید فیلد فرزند برای هر مقدار فیلد والد («Any») یا فقط برای مقدارهای مشخص نمایش داده شود. برای بازگرداندن انتخاب به **Any** روی **پاک کردن** کلیک کنید.

در این نمونه، فیلد فرزند **Sub دسته‌بندی** به‌محض انتخاب مقداری برای فیلد **دسته‌بندی** نمایش داده می‌شود.

#### تعیین اجباری‌بودن فیلد فرزند

شرط اجباری‌بودن فیلد فرزند را بر اساس مقدار فیلد والد تعیین کنید.

اگر شرط غیرفعال باشد، فیلد فرزند اجباری نیست. در صورت فعال‌بودن می‌توانید مشخص کنید فیلد برای هر مقدار والد (**Any**) یا فقط هنگام انتخاب مقدارهای مشخص اجباری شود. برای بازنشانی به **Any** روی **پاک کردن** کلیک کنید.

> توجه: اگر فیلد فرزند الزامی باشد، کاربر نمی‌تواند آن را خالی بگذارد.

در این نمونه، فیلد **Sub دسته‌بندی** فقط وقتی اجباری می‌شود که مقدار **دسته‌بندی** یکی از **Billing / Accounting / Payroll** باشد.

### استفاده از HD فرم Script در میزکار

میزکار را باز و به **HD فرم Script** بروید. DocType موردنظر، مانند **تیکت**، را انتخاب تا کد پایه نمایش داده شود. گزینهٔ **اعمال بر** را روی **فرم** بگذارید و گزینه‌های **Apply on جدید page** و **فعال** را فعال کنید. سپس handler مربوط به `onChange` را تعریف کنید.

فرض کنید دو فیلد از نوع انتخاب کردن به نام‌های **برنامه** و **دسته‌بندی** ساخته‌اید و می‌خواهید گزینه‌های **دسته‌بندی** بر اساس برنامهٔ انتخاب‌شده فیلتر شوند:

```js
function setupForm({doc, applyFilters}) {
    
    function update_category(value) {
        if(value=="ERPNext"){
            options = ["Manufacturing","Accounting","Selling","Purchase"]
        }
        else if(value =="Frappe Cloud"){
            options = ["Payment","Bench Down","Site Down", "FC Marketplace"]
        }
        else if(value== "HRMS") {
            options = ["Attendance","Shift","Tax"]
            
        }
        applyFilters("custom_category",options)
    }
    
    return {
        onChange:{
//          works only for new ticket page
            "custom_app":(newVal)=>update_category(newVal)
        }
    }
}
```

در نمونهٔ بالا، با تغییر فیلد `custom_app` تابع `update_category` اجرا می‌شود و مقدار تازهٔ `custom_app` را دریافت می‌کند. سپس با توجه به مقدار انتخاب‌شده، گزینه‌های فهرست کشویی با تابع `applyFilters` تغییر می‌کنند.

این تابع دو ورودی می‌گیرد:

1. فیلدی که می‌خواهید تغییر کند (می‌تواند از نوع انتخاب کردن یا Link باشد).
2. گزینه‌هایی که باید در فهرست کشویی نمایش داده شوند؛ املای درست آن‌ها را وارد کنید. اگر مقدار `null` باشد، گزینه‌ها به حالت پیش‌فرض بازمی‌گردند.

## چند سفارشی‌سازی دیگر

- برای پنهان یا نمایش‌دادن فیلد، از قابلیت `display_depends_on` در **Customize فرم** استفاده کنید. [راهنمای سفارشی‌سازی فرم](../erpnext/customize-form.md) و [ویدئوی آموزشی](https://www.youtube.com/watch?v=H_gWt0EPZCE) را ببینید.

  برای نمونه، شرط به‌روزرسانی دسته می‌تواند چنین باشد: `eval:doc.custom_app!==""`

- برای اجباری‌کردن یک فیلد بر اساس فیلدی دیگر، از `mandatory_depends_on` در **Customize فرم** استفاده کنید. برای جزئیات بیشتر، [مستندات DocField](https://docs.frappe.io/framework/user/en/basics/doctypes/docfield) را بخوانید.

  برای نمونه، برای اجباری‌کردن فیلد برنامه می‌توانید از این عبارت استفاده کنید: `eval:doc.ticket_type==="Bug"`

ویدئوی [نمونهٔ `mandatory_depends_on` و `display_depends_on`](https://www.youtube.com/watch?v=H_gWt0EPZCE) نیز این قابلیت‌ها را نشان می‌دهد.
