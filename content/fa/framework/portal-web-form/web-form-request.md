## درخواست فرم وب

**درخواست فرم وب** یک پیوند خصوصی برای یک **فرم وب** ایجاد می‌کند.

از آن وقتی استفاده کنید که فرم نباید کاملاً عمومی باشد، اما پاسخ‌دهنده باید بتواند بدون داشتن حساب کاربری آن را ارسال کند. برای نمونه، می‌توانید پیوند نظرسنجی رضایت مشتری را برای او بفرستید، مقدارهای مخصوص همان مشتری را از پیش در فرم قرار دهید و فیلدهای داخلی را از مرورگر پنهان نگه دارید.

## چه زمانی از آن استفاده کنیم؟

درخواست **درخواست فرم وب** مناسب است اگر:

1. پاسخ‌دهنده باید فرم را از طریق پیوندی خصوصی باز کند.
2. ممکن است پاسخ‌دهنده حساب کاربری نداشته باشد.
3. فرم باید مقدارهای مخصوص همان پاسخ‌دهنده را در بر بگیرد.
4. سند مقصد به مقدارهای پنهانی نیاز دارد که نباید در صفحهٔ وب افشا شوند.

## ساخت درخواست

یک **درخواست فرم وب** بسازید و **فرم وب** مربوط به آن را انتخاب کنید. یک کلید سازگار با URL به‌طور خودکار ساخته می‌شود.

درخواست می‌تواند این مقدارها را تعیین کند:

- **تاریخ انقضا:** تاریخ و زمان انقضای کلید درخواست.
- **فرم وب Values:** مقدارهای JSONای که در فرم وب نمایش داده می‌شوند و پاسخ‌دهنده می‌تواند آن‌ها را ویرایش کند.
- **Doc Values:** مقدارهای JSONای که هنگام ارسال فرم روی سند مقصد اعمال می‌شوند، اما به مرورگر فرستاده نمی‌شوند.

کلید درخواست در نشانی فرم وب به‌کار می‌رود:

```text
/your-web-form-route/new?web_form_request_key=<key>
```

می‌توانید این نشانی را از فرم **درخواست فرم وب** کپی کنید.

## اجباری‌کردن کلید

برای اجباری‌کردن کلید معتبر **درخواست فرم وب**، گزینهٔ **Key required** را در **فرم وب** فعال کنید.

اگر **Key required** فعال باشد و کلید معتبری ارائه نشود، فرم وب باز یا ارسال نمی‌شود.

اگر **ورود لازم است** نیز فعال باشد، هر دو شرط اعمال می‌شوند: کاربر باید وارد حساب خود شده باشد و یک کلید درخواست معتبر ارائه کند.

## مقدارهای ازپیش‌پرشده و پنهان

برای فیلدهایی که باید پاسخ‌دهنده ببیند، از **فرم وب Values** استفاده کنید. این فیلدها باید در جدول فیلدهای **فرم وب** درج شده باشند.

برای فیلدهایی که باید در سند ایجادشده تنظیم شوند، اما پاسخ‌دهنده نباید آن‌ها را ببیند، از **Doc Values** استفاده کنید. این فیلدها باید در DocType مقصد وجود داشته باشند.

کلیدهای JSON باید از نام‌های فنی فیلدها استفاده کنند؛ برای نمونه `customer` یا `survey_source`.

نمونه:

```json
{
 "customer": "CUST-0001",
 "survey_source": "Partner CSAT"
}
```

## انقضا و استفاده

اگر **تاریخ انقضا** تنظیم شده باشد، پس از آن تاریخ و زمان دیگر نمی‌توان از کلید درخواست استفاده کرد.

در یک فرم وب با پاسخ تکی، پس از ارسال موفق فرم، درخواست به‌عنوان استفاده‌شده علامت‌گذاری می‌شود و به سند مقصدِ ایجادشده پیوند می‌خورد. اگر تنظیمات **فرم وب** اجازه دهند، همین کلید بعداً برای ویرایش یا حذف آن پاسخ نیز قابل استفاده است.

اگر گزینهٔ **اجازه پاسخ‌های متعدد** در **فرم وب** فعال باشد، می‌توان کلید درخواست را برای چند ارسال دوباره به‌کار برد و کلید به یک سند مقصد مشخص پیوند نمی‌خورد.

## تنظیمات مرتبط فرم وب

- **اجازه پاسخ‌های متعدد:** اگر فعال باشد، یک کلید درخواست می‌تواند چند پاسخ را ارسال کند. در این حالت، **درخواست فرم وب** نمی‌تواند **نام سند مرجع** داشته باشد، چون یک درخواست ممکن است چند سند ایجاد کند.
- **Allow Editing پس از ارسال:** اگر فعال باشد، کلید درخواستِ پیوندخورده به یک پاسخ می‌تواند همان پاسخ را باز کند و ویرایش کند.
- **Allow حذف:** اگر فعال باشد، کلید درخواستِ پیوندخورده به یک پاسخ می‌تواند آن پاسخ را حذف کند.
