احراز هویت مبتنی بر توکن روشی امنیتی برای شناسایی کاربرانی است که می‌خواهند به سرور دسترسی پیدا کنند. این روش از نسخهٔ 11.0.3 در دسترس است. سرویس، توکن امنیتی را اعتبارسنجی می‌کند و درخواست کاربر را پردازش می‌کند.

## سازوکار احراز هویت

احراز هویت فرایندی است که در آن برنامه هویت کاربر را تأیید می‌کند. برنامه‌ها معمولاً هویت را با کوکی نشست نگه می‌دارند و به شناسه‌های نشستی متکی‌اند که در سمت سرور ذخیره شده‌اند. در نتیجه، توسعه‌دهنده باید فضای ذخیره‌سازی نشست را برای هر سرور جداگانه ایجاد کند یا لایه‌ای مستقل برای ذخیره‌سازی نشست به کار ببرد.

احراز هویت با توکن روشی جدیدتر است که برای رفع محدودیت‌های سازوکار ذخیره‌سازی شناسهٔ نشست در سمت سرور طراحی شده است. استفاده از توکن به‌جای شناسهٔ نشست می‌تواند بار سرور را کاهش دهد.

## عملیات ایجاد، خواندن، به‌روزرسانی و حذف توکن

به‌عنوان توسعه‌دهنده می‌توانید از توکن برای همهٔ عملیات ایجاد، خواندن، به‌روزرسانی و حذف (CRUD) استفاده کنید. پس از ایجاد توکن، می‌توان آن را برای مجازکردن درخواست‌های جداگانهٔ کاربران به کار برد. برنامه باید توکنی را که همراه هر درخواست فرستاده می‌شود اعتبارسنجی کند.

ترکیب **کلید API** و **رمز API** یک توکن می‌سازد. این توکن برای احراز هویت نزد برنامه استفاده می‌شود و می‌تواند درخواست‌های RPC و REST API را نیز احراز هویت کند.

## تولید توکن

برای هر کاربر می‌توانید یک کلید API و یک رمز API تولید کنید که در کنار هم توکن را تشکیل می‌دهند:

- کلید API: کاربر را شناسایی می‌کند.
- رمز API: اعتبار درخواست را تأیید می‌کند.

کلید API و رمز API را می‌توان از رابط وب، خط فرمان یا فراخوانی رویهٔ راه‌دور (RPC) تولید کرد:

- RPC:
  `/api/method/frappe.core.doctype.user.user.generate_keys?user="user_name"`
- خط فرمان:
  `bench execute frappe.core.doctype.user.user.generate_keys --args ['user_name']`
- رابط وب: **کاربر ← دسترسی API ← تولید کلیدها**

برای استفاده از توکن در درخواست API، مراحل همین راهنما را دنبال کنید.

**نکته‌ها:**

1. کلید API را نمی‌توان دوباره تولید کرد.
2. فقط کاربرانی که نقش **مدیر سیستم** دارند می‌توانند کلید تولید کنند.
