Frappe به‌همراه سامانهٔ احراز هویت کاربران ارائه می‌شود. این سامانه حساب‌های کاربری، مجوزهای مبتنی بر نقش و نشست‌های کاربری مبتنی بر کوکی را مدیریت می‌کند.

سامانهٔ احراز هویت Frappe به‌صورت پیش‌فرض قابلیت‌های زیادی دارد:

1. کاربر (`User`)
2. نقش (`Role`)
3. مجوزهای DocType
4. سطح مجوز
5. مدیر مجوزهای نقش
6. مجوزهای کاربر
7. محدودکردن نماها و فرم‌ها
8. هش‌کردن گذرواژه
9. بررسی استحکام گذرواژه
10. محدودکردن تلاش‌های ورود
11. احراز هویت شخص ثالث، مانند OAuth، Google و Facebook

## کاربر و نقش

رکورد `User` نمایندهٔ کاربری است که هویت او تأیید شده و می‌تواند کنش‌های مجاز را در سامانه انجام دهد. به هر کاربر می‌توان چند نقش اختصاص داد. `Role` مشخص می‌کند کاربر چه کنش‌هایی را روی یک DocType می‌تواند انجام دهد.

![نقش‌های کاربر](/files/user-roles.png) *نقش‌های کاربر*

برای نمونه، نقش **Blogger** روی DocType با نام **Blog Post** مجوز خواندن، نوشتن و ایجاد دارد؛ اما روی **Blog Category** فقط مجوز خواندن دارد.

![نقش Blogger](/files/role-blogger.png) *نقش Blogger*

## مجوزهای DocType

هنگام نصب برنامه می‌توان مجموعه‌ای از نقش‌های پیش‌فرض را به DocTypeها اختصاص داد. برای پیکربندی نقش‌های یک DocType، آن‌ها را در جدول **مجوزها** در خود DocType اضافه کنید.

![مجوزهای DocType](/files/doctype-permissions.png) *مجوزهای DocType*

با بازکردن ردیف، گزینه‌های بیشتری برای پیکربندی می‌بینید. ![جزئیات ردیف مجوزهای DocType](/files/doctype-permissions-detail.png) *جزئیات ردیف مجوزهای DocType*

در جدول زیر، این گزینه‌ها توضیح داده شده‌اند:

| گزینه | توضیح |
| --- | --- |
| سطح | [سطح مجوز](#سطح-مجوز) اختصاص‌یافته به این نقش |
| اگر کاربر مالک سند باشد | محدودیت‌ها فقط زمانی اعمال می‌شوند که همان کاربر سند را ایجاد کرده باشد |
| خواندن | اجازهٔ خواندن سند |
| نوشتن | اجازهٔ ویرایش سند |
| ایجاد کردن | اجازهٔ ایجاد سند |
| حذف | اجازهٔ حذف سند |
| ارسال | اجازهٔ ثبت نهایی سند |
| لغو | اجازهٔ لغو سند |
| اصلاح | اجازهٔ اصلاح سند |
| گزارش | اجازهٔ مشاهدهٔ نمای گزارش |
| برون‌بُرد | اجازهٔ برون‌بری رکوردها به Excel یا CSV |
| درون‌بُرد | اجازهٔ درون‌ریزی رکوردها با ابزار درون‌بُرد داده |
| تنظیم مجوزهای کاربر | اجازهٔ اعمال مجوزهای کاربر برای کاربران دیگر |
| اشتراک گذاری | اجازهٔ اشتراک‌گذاری سند با کاربران دیگر |
| چاپ | اجازهٔ چاپ سند یا تولید PDF |
| ایمیل | اجازهٔ ارسال ایمیل دربارهٔ سند |

## سطح مجوز

می‌توان از سطح‌های مجوز برای گروه‌بندی فیلدهای یک سند و اختصاص نقش‌های جداگانه به هر سطح استفاده کرد. به‌طور پیش‌فرض، مقدار `permlevel` همهٔ فیلدها 0 است.

![سطح مجوز](/files/permission-level.png) *سطح مجوز*

## مدیر مجوزهای نقش

مدیر مجوزهای نقش ابزاری برای مدیریت مجوزهای نقش است. مجموعهٔ پیش‌فرض مجوزها در این ابزار نمایش داده می‌شود و می‌توان آن‌ها را بازنویسی کرد.

![مدیر مجوزهای نقش](/files/role-permission-manager.gif)

## مجوزهای کاربر

مجوزهای کاربر مجموعهٔ دیگری از قواعد هستند که می‌توان برای هر کاربر جداگانه اعمال کرد. با آن‌ها می‌توان سندهایی را محدود کرد که در فیلد `Link` خود مقدار مشخصی دارند.

برای نمونه، فرض کنید می‌خواهید کاربر John فقط **Blog Post**هایی را ببیند که خودش ایجاد کرده است؛ یعنی پست‌هایی که نویسندهٔ آن‌ها **John** است. باید یک رکورد مجوز کاربر با مقادیر مناسب بسازید.

![نمونهٔ مجوزهای کاربر](/files/user-permissions-example-1.png) *رکورد مجوز کاربر*

پس از ایجاد پیکربندی مجوز کاربر، وقتی John وارد شود و فهرست Blog Postها را ببیند، فقط پست‌هایی برایش نمایش داده می‌شوند که خودش ایجاد کرده است.

![فهرست محدودشدهٔ Blog Post](/files/user-permissions-example-2.png) *فهرست محدودشدهٔ Blog Post*

## نقش‌های خودکار

برخی نقش‌ها به‌طور خودکار از کاربران پنهان می‌شوند؛ این کار نوشتن DocTypeهایی را که به مجوزهای فراگیر نیاز دارند ساده می‌کند. نقش‌های خودکار عبارت‌اند از:

1. **`Guest`** — این نقش به همه، ازجمله کاربران احراز هویت‌نشده، اختصاص دارد.
2. **`All`** — این نقش به همهٔ کاربران ثبت‌شده، ازجمله کاربران وب‌سایت، اختصاص دارد.
3. **`Administrator`** — این نقش فقط به کاربر `Administrator` اختصاص دارد که به‌طور پیش‌فرض ساخته می‌شود.
4. **کاربر پیشخوان (`Desk User`)** — [از نسخهٔ 15] این نقش به همهٔ کاربرانی اختصاص دارد که نوع کاربری آن‌ها «کاربر سامانه» است؛ یعنی کاربران سامانه‌اند، نه کاربران وب‌سایت.

## محدودکردن نماها و فرم‌ها

در Frappe Framework می‌توانید تعیین کنید کدام ماژول‌ها، DocTypeها و نماها برای کاربر قابل‌مشاهده باشند. برای تعیین ماژول‌های نمایش‌داده‌شده به کاربر، به بخش **اجازه ماژول‌ها** در فرم کاربر بروید.

![اجازهٔ ماژول‌ها در فرم کاربر](/files/allow-modules-in-user.png)

برای پنهان‌کردن یک DocType از کاربر، مجوز خواندن یک نقش را با [مدیر مجوزهای نقش](#مدیر-مجوزهای-نقش) حذف کنید.

برای کنترل مجوزهای صفحه‌ها و گزارش‌ها، از ابزار **مجوز نقش برای صفحه و گزارش** استفاده کنید.

![مجوز نقش برای صفحه و گزارش](/files/role-permission-for-page-and-report.png)

## هش‌کردن گذرواژه

Frappe هش‌کردن گذرواژه را به‌صورت پیش‌فرض انجام می‌دهد. گذرواژه‌ها رمزگذاری و در جدول جداگانه‌ای به نام `__Auth` ذخیره می‌شوند.

```sql
MariaDB [_baa0f26509a564b6]> select * from __Auth;
+---------+------------------+-----------+-----------------------------------------------
| doctype | name             | fieldname | password
+---------+------------------+-----------+-----------------------------------------------
| User    | Administrator    | password  | $pbkdf2-sha256$29000$Xss5pxSC8F5rDSHEOEdo7Q$in
| User    | test@erpnext.com | password  | $pbkdf2-sha256$29000$y7mXMoZQau09RwiBsLaWsg$h.
+---------+------------------+-----------+-----------------------------------------------
```

## خط‌مشی گذرواژه

Frappe استحکام گذرواژه را نیز بررسی می‌کند. برای فعال‌کردن این قابلیت، در بخش امنیت از **تنظیمات سیستم** استفاده کنید. فیلد حداقل امتیاز گذرواژه میزان استحکام لازم گذرواژه را می‌سنجد.

![خط‌مشی گذرواژه](/files/password-policy.png) *خط‌مشی گذرواژه*

## تلاش‌های ورود

در Frappe می‌توانید تعداد تلاش‌های پیاپی مجاز برای ورود را تعیین کنید. پس از رسیدن به این حد، حساب برای مدت مشخصی قفل می‌شود.

![تلاش‌های ورود](/files/login-attempts.png)

## احراز هویت شخص ثالث

Frappe از ارائه‌دهندگان ورود شخص ثالث پشتیبانی می‌کند. برای راه‌اندازی یک ارائه‌دهندهٔ ورود، باید یک **کلید ورود به سیستم اجتماعی** تنظیم کنید. [کلید ورود به سیستم اجتماعی](../guides/integration/social_login_key.md) را ببینید.
