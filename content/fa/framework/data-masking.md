در Frappe Framework می‌توان با استفاده از [سطح‌های مجوز (Perm Levels)](https://docs.frappe.io/erpnext/user/manual/en/managing-perm-level) مجوزها را طوری تنظیم کرد که مشخص شود چه کسی هر فیلد را ببیند.

بااین‌حال، در بسیاری از فرایندهای کاری لازم است بعضی فیلدها دیده شوند، اما دادهٔ حساس داخل آن‌ها پنهان بماند. برای نمونه:

- کاربران منابع انسانی ممکن است لازم باشد جزئیات کارمند را ببینند، اما مبلغ حقوق او را نبینند.
- کارکنان پشتیبانی ممکن است شمارهٔ تلفن مشتری را به‌شکل پوشانده‌شده‌ای مانند `811XXXXXXX` ببینند.
- کاربران مالی ممکن است به فیلدهای حساب بانکی دسترسی داشته باشند، بی‌آنکه شمارهٔ کامل حساب نمایش داده شود.

قابلیت **پوشاندن داده** برای همین کاربرد است.

با آن می‌توانید تعیین کنید که مقدار فیلدهای مشخص، بر اساس نقش‌ها و مجوزهای کاربر، پوشانده یا پنهان شود؛ بدون آنکه خود فیلد از دید کاربر خارج شود. به این ترتیب، اطلاعات حساس محافظت می‌شود و رابط کاربری همچنان یکدست و گویا می‌ماند.

### فعال‌کردن پوشاندن داده

می‌توانید پوشاندن داده را مستقیماً از DocType یا از طریق فرم Customize Form فعال کنید.

#### مراحل فعال‌سازی

1. DocType (در حالت Developer Mode) یا فرم Customize Formای را باز کنید که می‌خواهید پوشاندن داده را در آن فعال کنید.
2. فیلدی را که باید پوشانده شود انتخاب کنید.
3. گزینهٔ **Mask** را علامت بزنید.
4. فرم را ذخیره و دوباره بارگذاری کنید.

پس از فعال‌سازی، کاربرانی که مجوز **Mask** برای آن فیلد را ندارند، دادهٔ پوشانده‌شده یا پنهان را می‌بینند؛ کاربران دارای مجوز لازم، مقدار واقعی را خواهند دید.

در این ویدئو، فعال‌کردن پوشاندن داده نمایش داده شده است:

![فعال‌کردن Data Masking](/files/data-masking.gif)

#### نوع فیلدهای پشتیبانی‌شده

پوشاندن داده فقط برای نوع فیلدهای زیر قابل استفاده است:

`Select`، `Read Only`، `Phone`، `Percent`، `Password`، `Link`، `Int`، `Float`،
`Dynamic Link`، `Duration`، `Datetime`، `Currency`، `Data` و `Date`.

### برای توسعه‌دهندگان

پوشاندن داده در Frappe Framework با سیستم مجوزهای موجود کار می‌کند. اگر کاربر مجوز لازم برای پوشاندن یک فیلد را نداشته باشد، چارچوب مقدار واقعی آن را در رابط کاربری و پاسخ‌های backend به‌طور خودکار با نسخهٔ پوشانده‌شده جایگزین می‌کند.

#### سازوکار داخلی

1. **پیکربندی فیلد**  
   برای هر فیلد می‌توان ویژگی `mask` را در DocField فعال کرد:
   ```python
   {
       "fieldname": "phone_number",
       "fieldtype": "Data",
       "options": "Phone",
       "mask": 1
   }
   ```
2. **بررسی مجوز**  
   سیستم با این فراخوانی بررسی می‌کند که کاربر جاری مجوز `mask` را برای آن فیلد دارد یا نه:
   ```python
   meta.has_permlevel_access_to(fieldname=df.fieldname, df=df, permission_type="mask")
   ```
3. **پوشاندن خودکار در پاسخ‌ها**  
   اگر بررسی مجوز ناموفق باشد، چارچوب پیش از بازگرداندن مقدار، آن را به‌طور خودکار می‌پوشاند. این رفتار در موارد زیر اعمال می‌شود:

   - بارگذاری داده در نمای فرم
   - پرس‌وجوهای نمای فهرست
   - گزارش‌هایی که از ORM یا روش‌های استاندارد دریافت داده استفاده می‌کنند
   - پاسخ‌های API، مانند `/api/resource/...` و `/api/method/...`

> توجه: پوشاندن داده به‌طور خودکار روی پرس‌وجوهای سفارشی SQL یا پرس‌وجو گزارشهایی که SQL خام اجرا می‌کنند اعمال نمی‌شود. در این موارد، توسعه‌دهنده باید پیش از بازگرداندن نتیجه، منطق پوشاندن را صریحاً روی داده‌های پرس‌وجو اعمال کند.
