## کاربرد

```bash
bench trim-tables [OPTIONS]
```

## توضیح

حذف فیلدهای DocType ممکن است ستون‌های متناظر آن‌ها را از جدول‌های پایگاه داده پاک نکند. این رفتار برای جلوگیری از ازدست‌رفتن زودهنگام داده‌ها در Frappe عمدی است. بیشتر اوقات مشکلی ایجاد نمی‌کند، اما ممکن است انباشته‌شدن این داده‌ها بعداً دردسرساز شود.

پاک‌سازی منظم جدول‌ها این مزیت‌ها را دارد:

- کوچک‌ترشدن نسخه‌های پشتیبان؛
- کاهش زمان لازم برای تهیهٔ پشتیبان سایت؛
- کاهش فضای مصرفی پایگاه دادهٔ سایت؛
- بهینه‌شدن پرس‌وجوها در صورت استفاده از `SELECT *`؛
- پاک‌ماندن پایگاه داده از داده‌های پنهان یا تکراری.

این فرمان طرح‌وارهٔ جدول‌های پایگاه دادهٔ سایت را تغییر می‌دهد. به‌طور پیش‌فرض، پیش از تغییر جدول‌ها از کل پایگاه داده نسخهٔ پشتیبان می‌گیرد. اگر جدول‌ها به‌اشتباه تغییر کردند، می‌توانید با فرمان [بازیابی سایت (`bench restore`)](https://docs.frappe.io/framework/user/en/bench/reference/restore) سایت را به وضعیت پیشین برگردانید.

## گزینه‌ها

- `--format`، `-f`: قالب خروجی را تعیین می‌کند. قالب‌های JSON و متن در دسترس‌اند؛ مقدار پیش‌فرض متن است.

## پرچم‌ها

- `--dry-run`: ستون‌هایی را که حذف می‌شوند نشان می‌دهد.
- `--no-backup`: از سایت نسخهٔ پشتیبان نمی‌گیرد. با توجه به مخرب‌بودن این عملیات، استفاده از این گزینه توصیه نمی‌شود.

## نمونه

ممکن است ستون‌های باقی‌مانده فضای زیادی بگیرند. برای نمونه، هنگام سفارشی‌کردن DocType با خطای رسیدن به محدودیت اندازهٔ ردیف روبه‌رو شده‌اید و می‌خواهید مطمئن شوید ستون یتیم یا فیلد پنهان قدیمی وجود ندارد. برای پیش‌نمایش ستون‌هایی که حذف می‌شوند، اجرا کنید:

```bash
bench --site {site} trim-tables --dry-run
```
