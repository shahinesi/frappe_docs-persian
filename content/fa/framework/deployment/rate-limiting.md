Frappe Framework به‌صورت پیش‌فرض از محدودسازی نرخ درخواست‌های HTTP پشتیبانی می‌کند.

این سازوکار بر پایهٔ پنجرهٔ زمانی ثابت و مدت‌زمان صرف‌شده برای پردازش درخواست‌ها کار می‌کند. محدودیت روی مجموع زمان مصرف‌شده برای همهٔ درخواست‌های HTTP در پنجرهٔ پیکربندی‌شده اعمال می‌شود. چرخه پس از هر تعداد ثانیهٔ تعیین‌شده در `window` از نو آغاز می‌شود؛ برای نمونه، اگر `window` برابر 3600 ثانیه باشد، شمارنده در آغاز هر ساعت و بر اساس منطقهٔ زمانی سایت صفر می‌شود.

**نکته:** درخواست‌هایی که از حد مجاز فراتر بروند پردازش نمی‌شوند و پاسخ HTTP `429` (درخواست‌های بیش‌ازحد) دریافت می‌کنند.

برای فعال‌کردن محدودسازی نرخ در سایت، پیکربندی‌ای مانند نمونهٔ زیر را به `site_config.json` اضافه کنید:

```json
{
 "rate_limit": {
 "limit": 600,
 "window": 3600
 }
}
```

| کلید | توضیح |
|---|---|
| `limit` | بیشترین زمان مجاز برای مصرف در پنجرهٔ محدودسازی نرخ، بر حسب ثانیه. |
| `window` | طول پنجرهٔ محدودسازی نرخ، بر حسب ثانیه. |

سرآیندهای HTTP پاسخ هر درخواست، وضعیت فعلی محدودیت نرخ را نشان می‌دهند؛ برای مثال:

```
curl -i https://frappe.io/docs
HTTP/1.1 200 OK
X-RateLimit-Limit: 600000000
X-RateLimit-Remaining: 518060453
X-RateLimit-Reset: 3513
X-RateLimit-Used: 100560
```

اگر درخواستی پس از مصرف‌شدن سهمیهٔ پیکربندی‌شده ارسال شود، پاسخ HTTP `429` همراه با وضعیت محدودیت نرخ برگردانده می‌شود:

```
curl -i https://frappe.io/docs
HTTP/1.1 429 TOO MANY REQUESTS
X-RateLimit-Limit: 600000000
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1242
Retry-After: 1242
```

| سرآیند | توضیح |
|---|---|
| `Retry-After` | زمان باقی‌مانده تا بازنشانی پنجرهٔ محدودسازی فعلی، بر حسب ثانیه. |
| `X-RateLimit-Limit` | زمان مجاز در پنجرهٔ محدودسازی، بر حسب میکروثانیه. |
| `X-RateLimit-Remaining` | زمان باقی‌مانده برای مصرف در پنجرهٔ فعلی، بر حسب میکروثانیه. |
| `X-RateLimit-Reset` | زمان باقی‌مانده تا بازنشانی پنجرهٔ فعلی، بر حسب ثانیه. |
| `X-RateLimit-Used` | زمان صرف‌شده برای پردازش درخواست فعلی، بر حسب میکروثانیه. |

### محدودسازی نرخ برای هر endpoint

پیکربندی سراسری سایت، کل زمان پردازش درخواست‌ها را محدود می‌کند. توسعه‌دهندگان می‌توانند با decorator `@rate_limit` در `frappe.rate_limiter`، تعداد درخواست‌ها را برای متدهای پایتون مشخصی که در فهرست مجاز قرار گرفته‌اند، با محدودیت دقیق‌تری کنترل کنند.

**آرگومان‌های decorator:**

| آرگومان | نوع | پیش‌فرض | توضیح |
|---|---|---|---|
| `key` | `str` | `None` | کلیدی از `frappe.form_dict` برای شناسایی یکتای درخواست. |
| `limit` | `int` یا `Callable` | `5` | بیشترین تعداد درخواست در پنجرهٔ زمانی. |
| `seconds` | `int` | `86400` | طول پنجره بر حسب ثانیه؛ پیش‌فرض 24 ساعت است. |
| `methods` | `str` یا `list` | `"ALL"` | متدهای HTTP مشمول محدودیت؛ مانند `"POST"` یا `["GET", "POST"]`. |
| `ip_based` | `bool` | `True` | محدودیت را بر اساس IP درخواست‌کننده پیگیری می‌کند (آگاه از شبکه). |
| `endpoint` | `str` | `None` | *(افزوده‌شده در v17)* نام سفارشی شمارنده؛ اگر callable مسیر نقطه‌دار پایداری نداشته باشد (مانند `functools.partial`) الزامی است. |
| `user_based` | `bool` | `False` | *(افزوده‌شده در v17)* محدودیت را بر اساس شناسهٔ نشست کاربر واردشده پیگیری می‌کند (آگاه از هویت). |

**رفتار ردیابی و انحصار متقابل** *(ردیابی آگاه از هویت و سازوکار امن جایگزین برای مهمان از نسخهٔ 17 در دسترس‌اند. استفاده از `user_based` یا `endpoint` در v15 یا v16 باعث `TypeError` می‌شود.)*

محدودکنندهٔ نرخ هر درخواست را فقط بر اساس یکی از این دو هویت ردیابی می‌کند: هویت شبکه یا هویت کاربر؛ هر دو هم‌زمان به کار نمی‌روند.

- **آگاه از هویت (`user_based=True`):** محدودیت دقیقاً بر `frappe.session.user` واردشده اعمال می‌شود. IP درخواست‌کننده نادیده گرفته می‌شود؛ بنابراین کاربران یک شبکهٔ سازمانی مشترک (NAT) ناخواسته محدودیت یکدیگر را مصرف نمی‌کنند.
- **آگاه از شبکه (`ip_based=True, user_based=False`):** محدودیت فقط بر `request_ip` اعمال می‌شود و شناسهٔ نشست کاربر نادیده گرفته می‌شود. این رفتار قدیمی و پیش‌فرض است.
- **جایگزین برای مهمان:** اگر endpoint با `user_based=True` پیکربندی شده باشد، ترافیک ناشناس «Guest» به‌طور امن بر اساس IP ردیابی می‌شود. در نتیجه، یک مهمان مخرب نمی‌تواند با مصرف سهمیهٔ سراسری مهمان‌ها، برای همهٔ کاربران ناشناس اختلال منع سرویس ایجاد کند.

**نمونهٔ پیاده‌سازی:**

```python
from frappe.rate_limiter import rate_limit

# برای کاربران واردشده، سقف هر حساب 10 درخواست در دقیقه است.
# درخواست مهمان به این نقطهٔ پایانیِ دارای دو شیوهٔ احراز هویت، به 10 درخواست در دقیقه برای هر IP محدود می‌شود.
@frappe.whitelist()
@rate_limit(limit=10, seconds=60, user_based=True)
def generate_heavy_report():
    pass
```
