> تصویرهای رابط کاربری منبع از راه پیوند اصلی نمایش داده می‌شوند و در این مخزن بازنشر نشده‌اند؛ مجوز جداگانهٔ آن‌ها تأیید نشده است.

به‌محض ذخیره‌شدن رکورد User، فیلد **Email** غیرفعال می‌شود. برای تغییر آن، به‌جای ویرایش خود فیلد از **Rename** استفاده کنید. این کار نشانی ورود کاربر را بی‌درنگ تغییر می‌دهد: کاربر از همهٔ دستگاه‌ها خارج می‌شود و نشانی قبلی دیگر برای ورود یا بازنشانی گذرواژه پذیرفته نمی‌شود؛ بااین‌حال گذرواژهٔ او همان قبلی می‌ماند.

## چرا فیلد Email غیرفعال است؟

ایمیل User فقط یک فیلد نیست؛ شناسهٔ یکتای User (نام سند) هم هست؛ Frappe هنگام ساخت User مقدار `name` را برابر نشانی ایمیل قرار می‌دهد. همهٔ رکوردهایی که به User وابسته‌اند، از جمله تخصیص‌ها، مجوزها، مالکیت سند و ستون‌های `Created By` و `Modified By`، با همین شناسه پیوند دارند. تغییر مستقیم فیلد این پیوندها را خراب می‌کند؛ به همین دلیل Frappe فقط از مسیر **Rename** اجازهٔ تغییر می‌دهد. این عملیات شناسه و همهٔ رکوردهای ارجاع‌دهنده به آن را یک‌جا به‌روز می‌کند.

![فرم کاربر](https://docs.frappe.io/files/pasted-image-3qt4g4gv.webp)

## تغییر نشانی ایمیل کاربر

### پیش از شروع

- باید نقش **System Manager** را داشته باشید.
- نمی‌توانید حساب‌های **Administrator** یا **Guest** را تغییر نام دهید؛ بخش [اگر تنها حساب مدیر را اشتباهی تغییر نام داده‌اید](#اگر-تنها-حساب-مدیر-را-اشتباهی-تغییر-نام-داده-اید) را ببینید.

### مراحل

1. به **User List** بروید و Userی را باز کنید که می‌خواهید نشانی ایمیلش را تغییر دهید.
2. روی دکمهٔ **Menu (⋮)** در گوشهٔ بالای سمت راست فرم کلیک کنید.
3. **Rename** را انتخاب کنید.

   ![منوی تغییر نام](https://docs.frappe.io/files/pasted-image-t14k1h8e.webp)
4. نشانی ایمیل جدید را در فیلد **جدید Name** وارد کنید.

   ![فیلد نام جدید](https://docs.frappe.io/files/pasted-image-snm5kak0.webp)
5. روی **Rename** کلیک کنید.

Frappe شناسهٔ User و همهٔ رکوردهای پیوندخورده (تخصیص‌ها، مجوزها و تاریخچهٔ سند) را به نشانی جدید تغییر می‌دهد. این کار برای کاربری با تاریخچهٔ طولانی ممکن است چند ثانیه طول بکشد؛ هنگام اجرا زبانه را نبندید.

## پس از تغییر نام چه اتفاقی می‌افتد؟

- **کاربر از همه‌جا خارج می‌شود.** به‌محض پایان تغییر نام، Frappe همهٔ نشست‌های فعال او را در همهٔ مرورگرها و دستگاه‌ها خاتمه می‌دهد.
- **گذرواژه تغییر نمی‌کند.** کاربر با ایمیل جدید و گذرواژهٔ قبلی خود دوباره وارد می‌شود. ایمیل بازنشانی گذرواژه به‌طور خودکار ارسال نمی‌شود.
- **ایمیل قبلی بی‌درنگ از کار می‌افتد،** از جمله برای **Forgot Password**. در صورت استفاده، پیام `User does not exist` نمایش داده می‌شود؛ این رفتار موردانتظار است، چون دیگر رکوردی با آن نام وجود ندارد.
- **تاریخچهٔ سند حفظ می‌شود.** دیدگاه‌ها، تخصیص‌ها و سابقهٔ `Created By` و `Modified By` در سندهای موجود همچنان کاربر را درست، با ایمیل جدید، نشان می‌دهند.

## آیا دو User می‌توانند یک ایمیل داشته باشند یا ایمیل کاربر غیرفعال‌شده را دوباره استفاده کنند؟

1. ایمیل شناسهٔ سند User است و باید میان همهٔ Userها، حتی Userهای غیرفعال، یکتا باشد. اگر Userی را با ایمیلی بسازید یا تغییر نام دهید که از قبل استفاده شده است، حتی اگر متعلق به User غیرفعالی باشد، عملیات با پیام وجود شناسه شکست می‌خورد.

اگر چند نفر باید نامه‌های یک نشانی را بخوانند؛ مثلاً صندوق مشترک `sales@`، برای هر نفر User جداگانه‌ای با ایمیل یکتای خودش بسازید و از ارائه‌دهندهٔ ایمیل بخواهید نشانی‌هایشان را به همان صندوق مشترک هدایت کند: می‌توانید برای هر نفر نام مستعار جدا بسازید (مانند `sales-priya@` و `sales-arjun@`) یا اگر ارائه‌دهنده پشتیبانی می‌کند، از گونهٔ نشانی‌گذاری با علامت بعلاوه استفاده کنید (مانند `sales+priya@`). هر User همچنان نشانی ورود واقعی و یکتای خود را دارد و نامه‌های همه به یک صندوق می‌رسند.

به‌عنوان آخرین راه، اگر امکان ساخت نشانی‌های بیشتری ندارید، System Manager می‌تواند **Allow Login Using User Name** را در **System Settings → Login** فعال کند. در این صورت کاربران به‌جای ایمیل با Username وارد می‌شوند و می‌توان برای فیلد ایمیل مقدار جایگزین گذاشت. این تنظیم فقط روش ورود را عوض می‌کند: کاربران همچنان اعلان‌های سیستمیِ ارسال‌شده به آن نشانی جایگزین را دریافت نمی‌کنند و ایمیل باید برای هر User یکتا باشد.

## اگر تنها حساب مدیر را اشتباهی تغییر نام داده‌اید

حساب لفظی **Administrator** هرگز قابل تغییر نام نیست؛ Frappe آن را صریحاً مسدود می‌کند. بنابراین «ایمیل حساب مدیر تغییر کرده» همیشه یعنی یک User دارای سطح دسترسی System Manager تغییر نام داده یا دوباره ساخته شده است، نه خود Administrator.

اگر هنوز نشست فعالی دارید یا حساب System Manager دیگری در دسترس است:

1. با ایمیل **جدید** و **همان گذرواژهٔ قبلی** وارد شوید؛ تغییر نام گذرواژه را بازنشانی نکرده است.
2. اگر نمی‌دانید ایمیل جدید چه بوده، از System Manager دیگری بخواهید در **User List** با نام، شمارهٔ تلفن یا نقش، رکورد را پیدا کند و ایمیل فعلی را به شما بدهد.

اگر هیچ‌کس به حساب System Manager دسترسی ندارد:

- در Frappe Cloud، داشبورد را باز کنید، به **Notification → Requests** بروید و درخواست دسترسی سایت از پشتیبانی را تأیید کنید تا آن‌ها بتوانند حساب را پیدا یا بازنشانی کنند.
- اگر به سرور دسترسی دارید، System Manager می‌تواند گذرواژهٔ خود Administrator را مستقیماً بازنشانی کند: `bench --site [site-name] set-admin-password [new-password]`. این دستور گذرواژهٔ Administrator را بازنشانی می‌کند، نه کاربری را که تغییر نام داده‌اید. با آن دوباره به‌عنوان Administrator وارد شوید و حساب تغییرنام‌یافته را از آنجا اصلاح کنید.
