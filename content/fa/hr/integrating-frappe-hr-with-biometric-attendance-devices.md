## پیش‌زمینه

دستگاه بیومتریک، رویدادهای ثبت ورود و خروج کارمند را ذخیره می‌کند. Frappe HR این رویدادها را در سند [ثبت ورود و خروج کارمند](employee-checkin.md) نگهداری می‌کند.

سپس می‌توان بر پایهٔ رکوردهای ثبت ورود و خروج کارمند و [نوع شیفت](shift-type.md)، با استفاده از [حضور و غیاب خودکار](auto-attendance.md)، رکوردهای حضور و غیاب را ایجاد کرد.

برای اتصال دستگاه بیومتریک یا هر سامانهٔ کنترل دسترسی که رویدادهای ورود و خروج را جمع‌آوری می‌کند، این مراحل را انجام دهید.

## 1. تنظیم حضور و غیاب خودکار

پیش از واردکردن یا همگام‌سازی رویدادهای ورود و خروج کارمندان با Frappe HR، باید پروندهٔ کارمندان را ایجاد و شیفت‌هایشان را تنظیم کنید تا سامانه بتواند حضور و غیاب را خودکار ثبت کند.

برای تنظیم این قابلیت، [حضور و غیاب خودکار](auto-attendance.md) را ببینید.

پس از ایجاد پروندهٔ کارمندان و اختصاص شیفت به آن‌ها، می‌توانید به مرحلهٔ بعد بروید.

## 2. واردکردن رویدادهای دستگاه بیومتریک به Frappe HR

روش واردکردن رویدادها به قابلیت‌های دستگاه بیومتریک و سامانهٔ شما بستگی دارد. چند روش متداول:

### روش 1: استفاده از ابزار ورود داده

ساده‌ترین روش از نظر پیاده‌سازی این است که رویدادهای ورود و خروج را در فایل Excel یا CSV خروجی بگیرید و با ابزار داخلی ورود داده در Frappe HR، آن‌ها را در سند ثبت ورود و خروج کارمند وارد کنید. برای جزئیات، [واردکردن داده‌ها (درون‌بُرد داده)](../erpnext/data-import.md) را ببینید.

### روش 2: اتصال از طریق API

می‌توانید فرایند همگام‌سازی رویدادهای دستگاه بیومتریک را با API موجود در Frappe HR خودکار کنید. این روش به دانش فنی نیاز دارد؛ برای پیاده‌سازی ممکن است لازم باشد با مجری Frappe HR یا فروشندهٔ دستگاه بیومتریک مشورت کنید.

مراحل کلی:

1. در نمونهٔ Frappe HR خود یک [افزودن کاربران](../erpnext/adding-users.md) بسازید که برای ایجاد رویدادها از آن استفاده شود؛ این روش API به ورود کاربر نیاز دارد. مطمئن شوید کاربر مجوزهای لازم برای ایجاد سند ثبت ورود و خروج کارمند را دارد.
2. برای این کاربر **کلید API** و **رمز API** بسازید تا برای احراز هویت استفاده شوند.
3. برای کارمندان، **شناسهٔ دستگاه حضور و غیاب (شناسهٔ بیومتریک یا برچسب RF)** را مطابق دستگاه خود تنظیم کنید. جزئیات در [حضور و غیاب خودکار](auto-attendance.md) آمده است.
4. جزئیات پیاده‌سازی در [کد API](https://github.com/frappe/hrms/blob/d2529e03f92bf50efb65d3163bfcfdacbcf0b8f5/hrms/hr/doctype/employee_checkin/employee_checkin.py#L63-L109) موجود است. این API از مسیر زیر در دسترس است:

   ```text
   /api/method/hrms.hr.doctype.employee_checkin.employee_checkin.add_log_based_on_employee_field
   ```

5. اسکریپتی بنویسید که درخواست `POST` را به این API بفرستد. این نقطهٔ پایانی، کارمند متناظر با مقدار فیلد کارمند را پیدا می‌کند و سند ثبت ورود و خروج کارمند می‌سازد.

پارامترهای API:

| پارامتر | توضیح |
|---|---|
| `employee_field_value` | مقداری که باید در فیلد کارمند جست‌وجو شود. این مقدار همان شناسهٔ دستگاه حضور و غیاب است که در رویداد بیومتریک و پروندهٔ کارمند ثبت شده است. |
| `timestamp` | زمان ثبت رویداد. مقدار باید به‌صورت رشته و با قالبی مانند `2022-04-08 10:48:08.000000` فرستاده شود. |
| `device_id` | اختیاری؛ شناسهٔ مکان یا دستگاه. مقدار باید یک رشتهٔ کوتاه باشد. |
| `log_type` | اختیاری؛ جهت رویداد، اگر دستگاه آن را ارائه می‌دهد: `IN` یا `OUT`. |
| `skip_auto_attendance` | اختیاری؛ تعیین می‌کند این رویداد از پردازش حضور و غیاب خودکار کنار گذاشته شود یا نه: `0` یا `1`. |
| `employee_fieldname` | نام فیلد در DocType کارمند که جست‌وجوی کارمند بر اساس آن انجام می‌شود. مقدار پیش‌فرض `attendance_device_id` است. |
| `latitude` | اختیاری؛ عرض جغرافیایی مکان شیفت، اگر برای آن مکانی تعیین شده باشد. |
| `longitude` | اختیاری؛ طول جغرافیایی مکان شیفت، اگر برای آن مکانی تعیین شده باشد. |

پاسخ API، شیء سند ثبت ورود و خروج کارمندِ ایجادشده را برمی‌گرداند.

### روش 3: اجرای اسکریپت پایتون روی رایانه

می‌توانید اسکریپتی را روی رایانه اجرا کنید تا دستگاه‌های ZKTeco یا دستگاه‌های مشابه را به Frappe HR متصل کند.

- این روش فقط با دستگاه‌های ZKTeco یا دستگاه‌های مشابهی کار می‌کند که از ZKProtocol روی TCP/IP استفاده می‌کنند.
- اسکریپت در مخزن [frappe/biometric-attendance-sync-tool](https://github.com/frappe/biometric-attendance-sync-tool) در دسترس است. برای راه‌اندازی، دستورالعمل همان مخزن را دنبال کنید.
- این اسکریپت رویدادهای بیومتریک را از دستگاه پشتیبانی‌شده دریافت می‌کند و با API مرحلهٔ قبل به Frappe HR می‌فرستد.

## پرسش‌های متداول

### 1. چگونه دستگاه بیومتریک سازگار با Frappe HR را انتخاب کنم؟

اگر از روش 1 یا 2 استفاده می‌کنید، سازگاری دستگاه محدودیتی ایجاد نمی‌کند.

روش سوم از اسکریپتی استفاده می‌کند که با دستگاه‌های فهرست‌شده در [فهرست دستگاه‌های سازگار با pyzk](https://github.com/fananimi/pyzk#compatible-devices) سازگار است. معمولاً هر دستگاه ZKTeco یا دستگاه مشابهی که برای ارتباط TCP/IP از ZKProtocol استفاده کند، کار می‌کند. اگر ممکن است، پیش از خرید از فروشنده بخواهید دستگاه را با ابزار همگام‌سازی آزمایش کنید؛ سازگاری به چند عامل بستگی دارد.

### 2. کدام روش اتصال را انتخاب کنم؟

روش 1 در هر شرایطی قابل استفاده است، اما باید رویدادها را به‌صورت دوره‌ای و دستی وارد کنید. روش‌های 2 و 3 برای خودکارشدن همگام‌سازی به نظارت و یک‌بار راه‌اندازی نیاز دارند.

#### راه‌اندازی در یک مکان

در روش دریافت رویداد از دستگاه، ابزار باید بتواند از طریق TCP/IP با دستگاه بیومتریک ارتباط برقرار کند. معمولاً لازم است ابزار در همان شبکهٔ محلی دستگاه اجرا شود. سپس رویدادهای دریافت‌شده با دسترسی API به نمونهٔ Frappe HR همگام می‌شوند. این روش برای راه‌اندازی در یک مکان مناسب است.

#### راه‌اندازی در چند مکان

برای چند مکان، معمولاً روش 2 مناسب‌تر است؛ بسیاری از فروشندگان دستگاه بیومتریک خدماتی برای همگام‌سازی رویدادهای چند مکان با Frappe HR از راه API ارائه می‌کنند. روش 3، یعنی ابزار دریافت رویداد بیومتریک، در این حالت نیز قابل استفاده است، به‌شرط آن‌که با تنظیم شبکه آشنا باشید.
