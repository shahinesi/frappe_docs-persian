رویداد یا **محرک** تعیین می‌کند خودکارسازی چه زمانی آغاز شود. هر خودکارسازی دقیقاً یک محرک دارد. برای انتخاب آن، محرک بالای بوم را بزنید.

محرک‌ها در سه گروه **رکوردها**، **فعالیت** و **سایر موارد** قرار می‌گیرند.

![فهرست محرک‌ها در پنل کناری، گروه‌بندی‌شده در رکوردها، فعالیت و سایر موارد](https://docs.frappe.io/files/crm-automations-triggers-panel.png)

## رکوردها

این محرک‌ها با رخ‌دادن اتفاقی برای رکوردی از نوع سند خودکارسازی، اجرا را آغاز می‌کنند.

| محرک | زمان آغاز اجرا |
|---|---|
| **رکورد ایجاد شد** | رکورد تازه برای نخستین بار ذخیره شود. |
| **رکورد به‌روزرسانی شد** | رکورد موجود ذخیره شود. |
| **مقدار فیلد تغییر کرد** | مقدار فیلدی که انتخاب کرده‌اید عوض شود. |
| **رکورد حذف شد** | رکوردی حذف شود. |
| **رکورد ثبت نهایی شد** | رکوردی که ثبت نهایی دارد، ثبت نهایی شود. |
| **رکورد لغو شد** | رکورد ثبت‌نهایی‌شده لغو شود. |

### تغییر مقدار فیلد

**فیلد محرک** را برای پایش انتخاب کنید. همچنین می‌توانید شرط را محدودتر کنید:

- **از مقدار:** فقط هنگام تغییر فیلد از این مقدار اجرا شود. برای هر مقداری، خالی بگذارید.
- **به مقدار:** فقط هنگام تغییر فیلد به این مقدار اجرا شود. برای هر مقداری، خالی بگذارید.

برای نمونه، **وضعیت** در **معامله** (`CRM Deal`) را پایش کنید و **به مقدار** را روی «مذاکره» (`Negotiation`) بگذارید تا هر بار معامله وارد مرحلهٔ مذاکره شد اقدام شود.

> **رکورد به‌روزرسانی شد** در هر بار ذخیره اجرا می‌شود. اگر فقط تغییر یک فیلد برایتان مهم است، از **مقدار فیلد تغییر کرد** استفاده کنید تا خودکارسازی بیش از حد نیاز اجرا نشود.

## فعالیت

محرک‌های فعالیت رویدادهای CRM هستند که رخداد مهمی را برای سرنخ یا معامله نشان می‌دهند. هر محرک فقط برای نوع سندی که به آن مربوط است در دسترس خواهد بود.

| محرک | در دسترس برای | زمان آغاز اجرا |
|---|---|---|
| **برای مشتری احتمالی ایمیل فرستادیم** | سرنخ، معامله | ایمیل یا پیام WhatsApp برای سرنخ یا معامله فرستاده شود. |
| **مشتری احتمالی پاسخ داد** | سرنخ، معامله | ایمیل یا پیام WhatsApp از سرنخ یا معامله دریافت شود. |
| **سرنخ واجد شرایط شد** | سرنخ | وضعیت سرنخ به «واجد شرایط» تغییر کند. |
| **سرنخ به معامله تبدیل شد** | سرنخ | سرنخ به معامله تبدیل شود. |
| **مرحلهٔ معامله تغییر کرد** | معامله | وضعیت معامله تغییر کند. |
| **معامله برده شد** | معامله | معامله به وضعیتی از نوع «برد» برسد. |
| **معامله ازدست‌رفته شد** | معامله | معامله به وضعیتی از نوع «ازدست‌رفته» برسد. |
| **موعد کار گذشت** | سرنخ، معامله | موعد کاری که به سرنخ یا معامله پیوند دارد بگذرد و وضعیت آن «انجام‌شده» یا «لغوشده» نباشد. |

موعد کارها هر ساعت بررسی می‌شود؛ بنابراین اجرای محرک **موعد کار گذشت** ممکن است تا یک ساعت پس از موعد آغاز شود.

### داده‌های همراه رویداد فعالیت

هر رویداد فعالیت چند مقدار به نام **payload** همراه دارد که می‌توانید در متن گام‌ها با `{{ payload.<key> }}` به آن‌ها دسترسی پیدا کنید.

| رویداد | کلیدهای payload |
|---|---|
| برای مشتری احتمالی ایمیل فرستادیم / مشتری احتمالی پاسخ داد | `reference_doctype`، `reference_name`، `communication`، `channel` (`Email` یا `WhatsApp`)، `thread` |
| سرنخ واجد شرایط شد | `lead`، `status` |
| سرنخ به معامله تبدیل شد | `lead`، `deal`، `contact`، `organization` |
| مرحلهٔ معامله تغییر کرد | `deal`، `status`، `previous_status` |
| معامله برده شد | `deal`، `status` |
| معامله ازدست‌رفته شد | `deal`، `status`، `lost_reason` |
| موعد کار گذشت | `task`، `reference_doctype`، `reference_name`، `due_date` |

برای نمونه، خودکارسازی **مرحلهٔ معامله تغییر کرد** می‌تواند این پیام را برای تیم بفرستد:

```
{{ doc.name }} moved from {{ payload.previous_status }} to {{ payload.status }}
```

## سایر موارد

| محرک | زمان آغاز اجرا |
|---|---|
| **اجرای دستی** | فقط وقتی کاربر آن را برای یک رکورد اجرا کند. |
| **طبق زمان‌بندی** | بر پایهٔ زمان‌بندی تکرارشونده‌ای که با عبارت cron تعریف می‌کنید. |
| **در تاریخ مشخص** | چند روز پیش یا پس از تاریخی که در رکورد ثبت شده است. |
| **رویداد سفارشی** | وقتی برنامه رویداد نام‌داری را که انتخاب کرده‌اید منتشر کند. |

### طبق زمان‌بندی

یک **عبارت Cron** استاندارد پنج‌فیلدی وارد کنید:

| عبارت Cron | زمان اجرا |
|---|---|
| `0 9 * * 1` | هر دوشنبه ساعت 09:00 |
| `0 18 * * *` | هر روز ساعت 18:00 |
| `0 8 1 * *` | روز نخست هر ماه ساعت 08:00 |

### در تاریخ مشخص

**فیلد تاریخ**، **اختلاف تاریخ** بر حسب روز و **جهت تاریخ** (**پیش از** یا **پس از**) را انتخاب کنید. برای نمونه، «تاریخ پیش‌بینی‌شدهٔ پایان معامله، 3 روز، پیش از آن» سه روز قبل از تاریخ پیش‌بینی‌شده اجرا می‌شود.

### رویداد سفارشی

توسعه‌دهنده می‌تواند از برنامهٔ سفارشی خود رویداد را با `frappe.automation_engine.emit()` منتشر کند. نام رویداد را انتخاب کنید تا هر بار که منتشر شد، خودکارسازی آغاز شود. برنامه باید رویداد را از طریق hook به نام `automation_events` ثبت کند.

## انتظار برای رویداد در میانهٔ اجرا

می‌توان از رویدادهای فعالیت در داخل جریان نیز استفاده کرد، نه‌فقط برای آغاز آن. بلوک **انتظار برای رویداد** اجرا را متوقف می‌کند تا رویدادی مانند **مشتری احتمالی پاسخ داد** برای همان سرنخ، معامله یا رشتهٔ ایمیل رخ دهد. جزئیات در [راهنمای بلوک‌ها](blocks.md#wait-for-event) آمده است.
